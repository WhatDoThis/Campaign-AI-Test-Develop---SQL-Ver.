# 모듈 기능맵 — `new_ver/js` · `new_ver/jssp`

시연·프로토타입 발표 참고본. 코드 헤더를 풀어 쓴 안내서이며, 구현 정본은 각 파일 상단 주석이다.

관련: [`PRD.md`](./PRD.md) · `docs/report/01_개발가이드.md`

---

## 이 문서를 읽는 법

| 칸 | 의미 |
|---|---|
| **대분류** | `js` = 서버 엔진 · `jssp` = `/woo/` API·Studio UI |
| **소분류** | 파일 1개. **파이프라인에 등장하는 순**으로 나열 |
| **설명** | 그 파일이 시스템에서 하는 일 (1~2줄) |
| **기능 표** | 공개 API만. 내부 `_foo` 는 넣지 않음 |
| **순서** | 파일 안 순위가 아님. 아래 **전체 흐름 단계(00~17)** 번호 |

한 함수가 여러 단계에 쓰이면 `06 → 12` 처럼 적는다. **시작 단계 → 이후 재사용**.

---

## 전체 흐름 단계 (순서 번호)

마케터가 한국어를 넣으면 이 순서로 돈다. 미매칭이면 08~11을 한 바퀴 돈 뒤 07로 돌아온다.

```
00 부트 → 01 인증 → 02 UI → 03 컨텍스트
      → 04 슬롯추출 → 05 카탈로그 → 06 매칭 → 07 Plan
      → (미스) 08 Triage → 09 Tool → 10 Foundry → 11 발행 → 다시 07
      → 12 Compile → 13 Gate → 14 저장 → 15 유사 → 16 주입
      → 17 관리(운영 화면, 본선 밖)
```

| 순서 | 단계 | 하는 일 | 대표 모듈 |
|---|---|---|---|
| **00** | 부트 | 가드레일 상수 + LLM 시크릿을 `cfg` 로 합침 | Env · Config |
| **01** | 인증 | 세션·권한·CSRF·JSON 입출력 | Common |
| **02** | UI | Studio 화면·버튼·칩 표시 | Studio · StudioJs |
| **03** | 컨텍스트 | Program → Campaign → WKF 고르기 | StudioContext · WorkflowClone |
| **04** | 슬롯추출 | 문장 1회 번역 → 조건 칸(슬롯) | EnPivot |
| **05** | 카탈로그 | 슬롯마다 기존 fragment 후보 검색 | Fragments |
| **06** | 매칭 | 축·값·별칭이 맞는지 판정 (도메인 하드코딩 없음) | FragContract |
| **07** | Plan | 후보만 보고 CNF `plan_json` 작성. **SQL은 안 씀** | Llm · Generate |
| **08** | Triage | 미스 슬롯을 SQL로 만들 수 있는지 | Feasibility |
| **09** | Tool | 스키마/컬럼/값 조사 · 읽기 전용 SQL | Toolkit · Probe |
| **10** | Foundry | 새 fragment 생성 후 큐 처리 | Foundry · QueueStatus |
| **11** | 발행 | 중복 비교 → 버전 저장 | Dedup · Lifecycle · Embedding |
| **12** | Compile | plan + `sql_text` → 최종 audience SQL | Compiler |
| **13** | Gate | SELECT-only · `{{param}}` · SCOPE 검사 | Gates · Validate |
| **14** | 저장 | `ai_sql` 이력 · 큐 · GapLog | Repository |
| **15** | 유사 | 예전 WKF/SQL과 겹치는지 (Option 기본 OFF) | Match |
| **16** | 주입 | 락 → `ai-sql-id` Write → 이력 | Register · WorkflowUi |
| **17** | 관리 | fragment 승인·삭제 · GapLog(DB) | Review · Admin · FragmentAdmin |

흐름(텍스트):

```
한국어 NL
  → 04 EnPivot (슬롯 추출)
  → 05 Stage A (후보 검색)
  → 06 매칭
  → 07 Pass1 (plan_json)
       ↘ 미스면 08~11 Foundry 후 다시 07
  → 12 Compile → 13 Gate → 16 Register → WKF 액티비티
```

**발표용 한 줄:** LLM은 계획만 쓰고, SQL은 검증된 조각을 컴파일러가 조립한다. 없는 조건은 Foundry가 조각을 만든 뒤 같은 길을 다시 탄다.

### Pass0 · Pass1 이 무엇인가

PRD에서 LLM을 **두 번** 쓰는 이름을 그대로 둔 것이다. SQL을 쓰는 단계가 아니다.

| 이름 | 하는 일 | 지금 코드 |
|---|---|---|
| **Pass0** | 한 문장을 **조건 칸(슬롯)** 으로만 나눈다. fragment 이름·SQL 금지 | 기본은 `EnPivot.extractSlots` (문장 번역 1회). `Llm.decomposeSlots` 는 EnPivot이 없을 때만 폴백 |
| **Pass1** | Stage A가 좁혀 준 **후보 카드만** 보고, 어떤 조각을 어떻게 붙일지 **CNF `plan_json`** 을 쓴다 | `Llm.selectPlan` / `generatePlan` 후반. include · exclude · params |

한 줄로: **Pass0 = 문장 쪼개기, Pass1 = 조각 고르기.** 둘 다 SQL을 만들지 않는다. 최종 SQL은 **12 Compile**.
