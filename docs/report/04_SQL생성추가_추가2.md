## P0-2. sqlSelect 호출 규약 위반 (Adobe 공식문서 불일치) ★최우선
═══════════════════════════════════════════
공식 시그니처: `sqlSelect(format, query [, dataSource])`
- `format` = 결과 XML 스키마 정의 `"docName,[fieldXPath:type[:length],]*"` (라벨 아님)
- 반환값 = **XML 객체** (배열 아님). `.length` / `[0]` 접근 불가.
- 공식 예: `sqlSelect("publicUrl,@sstringValue:string", "select ...")`
           → `res.publicUrl.@sstringValue.toString()`

현재 코드는 첫 인자에 `"probe"`, `"probe_values"` 같은 **라벨**을 넘기고 결과를 배열처럼
순회하고 있어, 값이 항상 빈 배열로 나온다. (예외는 안 나므로 조용히 오작동)

### (a) new_ver/js/testWooProbe.js
- `_safeSqlSelect(label, query)` → `_safeSqlSelect(format, query)` 로 의미 변경.
  반환은 `{ok:true, xml: <XML>}` 로 바꾼다. rows 개념 제거.
- 존재 검증 쿼리는 결과를 쓰지 않으므로 format 을 고정 지정:
```
var existsQ = "SELECT * FROM (" + inner + ") tw_probe WHERE 1=0";
var ex = _safeSqlSelect("row", existsQ);   // 예외 발생 여부만 확인
```
- 샘플 조회는 **컬럼 별칭을 고정**하고 format 을 맞춘다:
```
var sampleInner = "SELECT " + kc + " AS tw_key FROM (" + inner + ") tw_sample";
var sampleQ = dial.limit(sampleInner, lim);
var sampR = _safeSqlSelect("row,@tw_key:string", sampleQ);
var sample = [];
if (sampR.ok && sampR.xml) {
  for each (var r in sampR.xml.row) {
    sample.push(String(r.@tw_key));
  }
}
```
- 기존 `row.length` / `row[0]` / `row[kc]` 접근 코드 전부 제거.

### (b) new_ver/js/testWooToolkit.js — `_toolProbeValues`
```
var inner = "SELECT DISTINCT " + columnName + " AS tw_val FROM " + tbl +
            " WHERE " + columnName + " IS NOT NULL";
var q = testWoo.probe.dialect().limit(inner, limit);
var xml = sqlSelect("row,@tw_val:string", q);
var values = [];
for each (var r in xml.row) { values.push(String(r.@tw_val)); }
```
- 반환 `{ok, distinctCount, values, truncated, highCardinality}` 형태는 유지.

### (c) 그 외 sqlSelect 호출부 전수 점검
- 저장소 전체에서 `sqlSelect(` 를 grep 하여 첫 인자가 format 규격인지 확인하고 전부 교정.
- 각 호출마다 SELECT 절에 **명시적 별칭(AS tw_xxx)** 을 부여하고 format 과 1:1 대응시킬 것.

### (d) 실측 확인 태스크 (코드 확정 전)
- 임시 WF JS 액티비티에서 아래를 실행하고 반환 XML 구조를 logInfo 로 출력:
```
var t = sqlSelect("row,@x:string", "SELECT 1 AS x");
logInfo(t.toXMLString());
```
- 실제 루트/노드명이 위 가정과 다르면 파싱 코드를 그 결과에 맞춰 확정.

### 신규: testWooProbe.js 에 `preflight()` 추가
```
function preflight() {
  try {
    sqlGetInt("SELECT 1");
  } catch (e) {
    return { ok: false, code: "NO_SQL_RIGHT",
      message: "Foundry 실행 오퍼레이터에 'sql' named right가 없습니다. " +
               "관리자에게 권한 부여를 요청하세요. (원인: " + String(e.message || e) + ")" };

  try {
    sqlSelect("row,@x:string", "SELECT 1 AS x");
  } catch (e2) {
    return { ok: false, code: "NO_SQL_SELECT_RIGHT",
      message: "sqlSelect 실행 권한이 없습니다: " + String(e2.message || e2) };

- `processQueueItem()` 진입 시에도 호출. 실패 시 큐를 `failed` + 위 message 를 last_error 에 기록.
- 일반 SQL 오류와 **구분되는 errId 접두사**(`FFPERM`) 사용.

### 문서

## P1-1. 순차 생성 후 Stage A 재실행 누락
═══════════════════════════════════════════
파일: testWooFoundry.js — 슬롯 순회 루프

현재는 `clearCache()` 만 호출하고 남은 슬롯 재검색을 하지 않아,
"앞서 만든 fragment 가 뒤 슬롯을 커버하면 생성 스킵" 설계가 동작하지 않는다.

### 수정
fragment 발행(publish) 성공 직후:
```
testWoo.fragments.clearCache();
var stillMissing = [];
for (var k = 0; k < remaining.length; k++) {
  var hit = testWoo.fragments.searchSlots([remaining[k]]);   // 기존 Stage A 함수 재사용
  if (hit && hit.length && hit[0].candidates && hit[0].candidates.length) {
    slotResults.push({ slotId: remaining[k].id, verdict: "feasible",
      resolvedBy: "reuse_after_publish", fragmentId: hit[0].candidates[0].id });
    continue;                       // 생성 불필요
  }
  stillMissing.push(remaining[k]);
}
remaining = stillMissing;
```
- splice + si-- 패턴은 제거하고 위 방식으로 교체한다.
- `maxNewFragments` 카운트는 **실제 publish 된 건수만** 증가시킨다.

## P1-4. dedup population 계산 오류 (판정 뒤집힘)
═══════════════════════════════════════════
파일: testWooDedup.js — `check()`

현재: `population = probeNew.total` (후보 fragment 결과 건수) → ratio 가 과대평가되어
명백한 near 가 novel 로 빠진다.

### 수정
```
function _population() {
  if (_popCache != null) return _popCache;
  var cfg = testWoo.cfg.getConfig();
  var sql = cfg.foundry.populationCountSql;   // 이미 Config 에 존재
  try { _popCache = sqlGetInt(sql); } catch (e) { _popCache = 0; }
  return _popCache;
}
```
- 모듈 스코프에 `var _popCache = null;` 선언, `check()` 진입 시 캐시 재사용.
- `ratio = bestDiff / _population()` 로 교체. population 이 0 이면 판정을 `near` +
  `delegateHuman:true` 로 처리(임계 계산 불가).
- `probeNew` 는 population 용도로 쓰지 말 것(다른 용도로만 유지).

## P1-5. Triage evidence 를 LLM 자기신고에 의존 (강등 우회 가능)
═══════════════════════════════════════════
파일: testWooFeasibility.js — `applyDemotionRules`

현재 강등 판정이 LLM 이 JSON 으로 써준 `evidence.valueProbes` 를 신뢰한다.
LLM 이 툴 호출 없이 값을 지어내면 강등을 우회한다.

### 수정
- `applyDemotionRules(raw, toolCallCount)` → `applyDemotionRules(raw, toolLog)` 로 변경.
- 실제 호출 여부 판정 헬퍼 추가:
```
function _hasToolCall(log, name) {
  for (var i = 0; i < log.length; i++) {
    if (log[i] && String(log[i].tool) === name) return true;
  }
  return false;
}
```
- 강등 규칙 교체:
```
if (verdict === "no_value"  && !_hasToolCall(toolLog, "probe_values"))    demote();
if (verdict === "no_column" && !_hasToolCall(toolLog, "search_columns"))  demote();
if (verdict === "feasible"  && toolLog.length === 0)                      demote();
if (verdict === "feasible"  && confidence === "low")                      demote();

  `evidence.selfReportMismatch = true` 로 표시하고 narrative 에 부기.

## P1-6. resetBudget 중복 호출로 툴 예산 무력화
═══════════════════════════════════════════
`feasibility.runTriageLoop` 와 `foundry.runToolLoop` 가 각각 `resetBudget()` 을 호출해
예산이 슬롯·단계마다 초기화된다(요청당 20회 → 실질 수십~수백회).

### 수정 — testWooToolkit.js
- `resetBudget()` 를 두 개로 분리:

- `foundry.runToolLoop` 시작 시 `markPhase("generate:" + slotId)`.
- 두 함수 내부의 `resetBudget()` 호출 **삭제**.

## P2-1. XML 파싱을 정규식 → E4X 로 전환
═══════════════════════════════════════════
파일: testWooToolkit.js — `_toolDescribeSchema`, `_toolSearchColumns`, `_resolveSqlTable`

현재 정규식이 `name`/`label`/`type` 속성 **순서를 고정 가정**하고, label 없는 attribute 는
누락된다. ACC 스키마는 속성 순서가 자유롭다.

### describe_schema
```
var sch = application.getSchema(schemaId);   // XML 객체
var cols = [];
for each (var a in sch..attribute) {
  cols.push({
    name:  String(a.@name),
    label: String(a.@label || ""),
    type:  String(a.@type || "string")
  });
  if (cols.length >= 120) break;
}
var links = [];
for each (var l in sch..element) {
  if (String(l.@type) === "link") {
    links.push({ name: String(l.@name), target: String(l.@target || "") });
  }
}
```
- 반환 JSON 직렬화 후 **4KB 초과 시 절단 + `{truncated:true}`** 표시(기존 규칙 유지).

### _resolveSqlTable
- 정규식 `sqltable=` 첫 매칭 사용 금지(하위 element 의 값이 잡힐 수 있음).
```
var root = sch.element.(@name == String(sch.@name))[0];
var tbl = root ? String(root.@sqltable || "") : "";
if (!tbl) tbl = String(sch.element[0].@sqltable || "");
```
- 비어 있으면 `{error:"sqltable not resolvable for " + schemaId}` 반환.

### search_columns
- 동일하게 E4X 순회로 교체. 한글 label / 영문 name 양쪽 부분일치 유지.

## P2-3. 402/429 판정을 문자열 검색 → HTTP 상태코드
═══════════════════════════════════════════
파일: testWooLlm.js / testWooFoundry.js

현재 `msg.indexOf("402") >= 0` 방식은 SQL 오류 메시지 등에 우연히 매칭될 수 있다.

### 수정
- `postChat` / `postEmbedding` 이 오류 시 던지는 Error 에 상태코드를 실어 보낸다:
```
var err = new Error("[testWoo.llm] HTTP " + code + ": " + bodyShort);
err.httpStatus = code;       // 402 / 429 / 5xx
err.isRateLimited = (code === 429);
err.isOutOfCredit = (code === 402);
throw err;
```
- Foundry catch 블록:
```
var status = "failed";
if (e && (e.isRateLimited || e.isOutOfCredit)) status = "throttled";
```
- `throttled` 은 attempt_count 를 증가시키지 않는다(자동 재시도 금지 원칙 유지).

## P2-4. GapLog 개념 정규화 부실

현재 소문자화만 하여 "최근 3개월 내 가입" / "최근 3개월내 가입" 이 별개 레코드가 된다.

### 수정
```
function _normalizeConcept(s) {
  var t = String(s || "");
  t = t.replace(/\s+/g, "");                    // 공백 전부 제거
  t = t.replace(/[.,!?~·\-_/()\[\]]/g, "");     // 구두점 제거
  t = t.replace(/(을|를|이|가|은|는|의|에|에서|으로|로|와|과|한|인)$/g, ""); // 말미 조사
  return t.toLowerCase();
}
```
- 기존 GapLog 레코드는 마이그레이션하지 말고, 신규부터 적용(로그에 명시).
