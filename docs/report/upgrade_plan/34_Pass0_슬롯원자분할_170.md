# #170 — Pass0 슬롯 원자 분할

> 슬롯 1개 = 조건 축 1개. Foundry/서가 재사용의 **전제**.  
> LLM 프롬프트만 믿지 않고 **결정적 `normalizeAtomicSlots`** 로 보정한다.

---

## 0. 왜 필요한가

| 잘못된 슬롯 | 결과 |
|---|---|
| `20대 남성` 1슬롯 | Foundry가 age+gender JSON을 한 번에 냄 · gender 미생성 |
| Pass0 “MAY keep one slot” | 제품 경로가 복합 슬롯을 허용 |

합침(AND)은 **Compiler**. 쪼개기는 **Pass0(+정규화)**.

---

## 1. 규칙

| ID | 규칙 |
|---|---|
| S1 | 슬롯 1 = 축 1 (region / plan / age / gender / other) |
| S2 | `20대 남성` → `20대` + `남성` |
| S3 | `30대 50대` / `30~50대` → **age 슬롯 1개** (`30대~50대`) |
| S4 | 미지 축(홈페이지 방문 등)은 `other`로 유지 · 삭제 금지 |
| S5 | 컬럼명 하드코딩 금지. NL 축 힌트(지역명·요금제·연령대·성별 표현)만 사용 |

---

## 2. 구현

| 위치 | 내용 |
|---|---|
| `testWooLlm.normalizeAtomicSlots` | 결정적 분할·중복 제거·id 재부여 |
| `decomposeSlots` | 프롬프트 #170 + LLM 결과 정규화 |
| `generatePlan` | `unmatchedSlots`(객체) — 큐잉용 |
| `testWooAiGenerate.jssp` | `missing_slots_json` ← unmatchedSlots |
| Foundry `_normalizeSlots` | 큐 진입 시 동일 정규화(방어) |

---

## 3. HUMAN 검증

| ID | 입력 | 기대 슬롯(텍스트) |
|---|---|---|
| V1 | `서울에 사는 Z요금제 쓰는 20대 남성 고객` | 서울 / Z요금제 / 20대 / 남성 |
| V2 | `20대 남성` (한 덩어리로 LLM이 내도) | 20대 / 남성 |
| V3 | `홈페이지 방문한 Y요금제 30대 50대 고객` | 홈페이지… / Y요금제 / 30대~50대 |
| V4 | gender frag 없는 상태 V1 | unmatched에 **남성만**(또는 미보유 축만) · age와 섞인 1슬롯 금지 |

증명: 큐 `slots_json` / `missing_slots_json` · Studio unmatched 문구.
