#### 1-B. 미사용 판정 절차 (기계적)

1. 파일 basename으로 `new_ver` 전체 `rg` — import/loadLibrary/soap/form ref/href 0건
2. JSSP면 `/woo/<name>.jssp` 문자열 참조 0건
3. schema면 `woo:<name>` 참조 0건 + navtree/form 미사용
4. JS면 `loadLibrary` / `testWoo.xxx` 심볼 참조 그래프에서 리프인지
5. **의심만으로 삭제 금지** — 표에 `판정=후보` 후 HUMAN 확인 → `확정`

### Step 2 — `_폐기` 개명 (CLEAN-9-2)

규칙:

| 현재 | 폐기 후 |
|---|---|
| `foo.bar.xml` | `foo_폐기.bar.xml` 또는 `foo.bar_폐기.xml` → **권장: `foo_폐기.bar.xml`** (확장자 앞) |
| `testWooXtkWorkflowButtonPatch.xml` | `testWooXtkWorkflowButtonPatch_폐기.xml` |
| `testWooAiAuthDebug.jssp` | `testWooAiAuthDebug_폐기.jssp` |

- `git mv` 사용. 내용 대규모 수정과 개명을 한 커밋에 섞지 말 것(가드레일: docs/code 혼입 금지와 별도로, 폐기는 **개명 커밋 / 콘솔삭제 기록 커밋** 분리 권장).
- 개명 직후 `rg`로 구 파일명 참조가 남으면 FAIL — 참조 제거 또는 폐기 철회.
- (선택) 개명 후 `new_ver/_폐기/` 아래로 이동해 활성 트리와 분리.

### Step 3 — Campaign 콘솔 삭제 (CLEAN-9-3) — HUMAN_CONSOLE 핵심

Agent는 삭제 완료를 스스로 PASS 처리하지 않는다. 유형별 순서:

| 유형 | 콘솔 위치(일반) | 조치 |
|---|---|---|
| Input form | Administration > Configuration > Input forms | 해당 `woo:*` 폼 **Delete** 또는 연결 해제 |
| Navtree command/node | Navigation hierarchies | 폐기 command/node 제거 후 저장·재로그인 |
| JSSP | 해당 네임스페이스 페이지 | 페이지 삭제 또는 비활성. URL 북마크 안내 |
| JS library | Administration > Configuration > JavaScript codes | 라이브러리 삭제(다른 lib가 loadLibrary 하지 않는지 확인 후) |
| Schema | Data schemas | **확장/데이터 스키마 삭제는 DB structure·데이터 영향** — 기본은 콘솔에서 숨김/미사용 표시만. 물리 DROP은 HUMAN 별도 승인 |
| WF form patch | xtk:workflow 폼 | 8차 역패치가 끝났는지 재확인 후 잔여 버튼/ref 제거 |
| Options | Options | `testWooAi*` 중 폐기 전용 키 삭제 |

**삭제 순서 권장**: navtree/command → form/JSSP → JS → (스키마는 최후·신중)

### Step 4 — 검증 (CLEAN-9-4)

- Foundry/Generate 스모크 최소 1건
