## 2. 사실 기록 [F-1]~[F-10]

### [F-1] 임베딩 모듈 존재
- **사실**: `new_ver/js/testWooEmbedding.js`에 embed / normalize / cosine / embedTextOf / ensureEmbedding / sourceHash 구현.
- **판정**: 정상(코드 존재).

### [F-2] env 플래그·모델
- **사실(조사 시점)**: `testWooEnv.js` `llm.embedEnabled = true`, `embedModel = "openai/text-embedding-3-small"`.
- **조치(#155 Task1)**: `embedEnabled → false` + 사유 주석. **현재 repo = false**.
- **판정**: 조사 시점=활성 결함유발 · 조치 후=차단 정상.

### [F-3] Config 노출·과거 오참조
- **사실**: `testWooConfig.js`가 `cfg.llm.embedEnabled` / `embedModel` 노출. 과거 `cfg.foundry.embedEnabled` 오참조는 Embedding 주석에 명시·수정됨.
- **판정**: 정상.

### [F-4] postEmbedding
- **사실**: `_embedEndpoint`가 chat URL의 `/chat/completions`를 `/embeddings`로 치환. 패턴 불일치 시 구버전은 chat URL 재사용(→400/404). body=`{model,input}`, Bearer, `_postJson` 동기. 구버전은 `JSON.parse`만·`wrap.error` 미검사.
- **조치(#155 Task3-4/5)**: 불일치→`null` · `wrap.error`→`_httpError`(402/404/429 구분 가능) · `embed()` catch로 null 폴백.
- **판정**: 구=결함 · 조치 후=정상(코드).

### [F-5] OpenRouter embeddings API
- **사실**: OpenRouter는 `POST /api/v1/embeddings` 지원. 모델 `openai/text-embedding-3-small` 카탈로그 존재. 문서상 402/404/429, 스트리밍 미지원, **Cache embeddings** 권고.
- **URL**: https://openrouter.ai/docs/api_reference/embeddings
- **판정**: 외부문서 근거(정상 참고).

### [F-6] 유일 소비처 = dedup L2
- **사실**: `testWooDedup.js` — L0 contentHash → L1 jaccard → L2 embedding → L3 대칭차 → L4 LLM 설명. 최종 verdict는 해시·대칭차가 결정. L2는 L1 상위 정렬만. `vec==null`이면 `l2:0`으로 진행.
- **판정**: 정상(설계). 품질 기여=정렬뿐.

### [F-7] 임베딩 텍스트 범위
- **사실**: fragment `label`+`description`+`tags`만. `sql_text`·마케터 `nl_request` 아님.
- **판정**: 정상(범위 명시).

### [F-8] 스키마 emb_* 5필드
- **사실**: `woo:testWooAiFragment` — `emb_vector`(memo), `emb_model`, `emb_dim`, `emb_source_hash`, `emb_updated_at`. dedup `_loadCandidates`가 `@emb_vector`/`@emb_source_hash` select.
- **판정**: 스키마 정상 · 저장 경로가 문제였음.

### [F-9] 영속화 결함 (P1)
- **사실(조사 시점)**: `ensureEmbedding`이 JS 객체에만 대입. `lifecycle.publish()`에 emb_* Write 없음. `emb_updated_at` 세팅 코드 없음 → DB 상시 공백 → 캐시 조건 상시 false → check()당 최대 후보8+신규1=**최대 9회** 재임베딩.
- **조치(#155 Task3-1/2)**: publish에 emb_* 조건부 Write · ensureEmbedding에 `emb_updated_at`.
- **미해결(Task3-3)**: dedup이 **기존 후보**를 재계산했을 때 fragment 레코드에 되쓰는 배치는 **이번 범위 제외**. publish(신규 발행) 경로만 정상화.
- **판정**: 조사=결함 · publish 경로 조치됨 · 후보 배치 갱신=미해결.

### [F-10] WKF 조건 매칭과 무관
- **사실**: `testWooMatch.js`에 임베딩 호출 없음. #152 name Jaccard 오탐과 인과관계 없음. 임베딩 ON/OFF로 그 오탐은 해결되지 않음.
- **판정**: 미사용(매칭). 품질 이슈는 #154 소관.

## 3. 비용 영향

| 항목 | 값 |
|---|---|
| 이론상 상한 | `dedup.check()` 1회 = 신규 1 + L1 상위 후보 ≤8 → **최대 9 임베딩 호출** |
| 캐시 미스 시 | 조사 시점(영속화 전) = **상시 전량 미스** |
| 실제 호출 횟수 | **측정 필요** (저널/프록시 미계측) |
| 금액 | **기재하지 않음** (임의 추정 금지) |

Task1 `embedEnabled=false` 후: 임베딩 HTTP **0회**(회귀: L2=0, verdict 불변).

## 4. OpenRouter “Cache embeddings” 권고

공식 문서(Embeddings API)는 동일 텍스트가 결정적(deterministic)이므로 **임베딩을 저장·재사용**하여 재생성을 피하라고 권고한다.

- Ref: https://openrouter.ai/docs/api_reference/embeddings

본 시스템의 스키마 `emb_*` + `emb_source_hash` 캐시 설계는 이 권고와 정합하나, **publish 미저장**으로 권고를 위반하고 있었다(#155로 publish 경로 교정).

## 5. 결론 (1문단)

현재(그리고 설계상) 임베딩은 **Fragment Foundry dedup의 L2 정렬**에만 쓰이며, **최종 duplicate 판정(exact/equivalent/near/novel)을 바꾸지 않는다.** Studio WKF 조건 매칭(`testWooMatch`)에는 **관여하지 않으므로** 서울/인천 오탐 해결과 무관하다. 영속화 부재 시에는 품질 이득 없이 호출만 반복하는 구조였고, Task1로 과금을 차단한 뒤 Task3로 publish 저장을 넣었다. **`embedEnabled`를 다시 true로 올리는 것은 HUMAN 스모크(publish 후 `@emb_source_hash` 비공백 · 재check 시 임베딩 0회) + 사용자 승인 후에만** 한다.
