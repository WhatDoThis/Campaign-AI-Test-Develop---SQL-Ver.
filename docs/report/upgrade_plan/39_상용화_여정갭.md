> **상태:** 문서. 남은 실행 순서는 `41_완성로드맵.md`.

## 0. 왜 이전 %가 낮게 보였나

이전 집계는 **현행 실행 키 25개 중 repo `[x]`** 만 셌다.  
`#164~#174`와 `#175` G1~G6이 그 분모의 절반이라, 추출이 끝나면 전체가 끝난 것처럼 보였다.

운영자가 말한 빈칸(WKF 열기, 액티비티 반영, 목록 클릭, 임시→새 SQL, 멘트)은 대부분 **트랙 B R5~R8 + UX** 이고, 키 개수로는 4개처럼 보여도 **사용자 여정의 후반 전부**다.

| 축 | 대략 | 의미 |
|---|---|---|
| 추출 (조건→SQL) | ~95% | Studio 게이트 + sql_validate_wkf 실DB 타겟 추출 HUMAN PASS |
| 셸·커밋 (SQL→WKF) | ~40% | R6 repo. HUMAN 전(반영·락·덮어쓰기) |
| 상용 (E2E+카피+운영) | ~20% | 목록 UX·멘트·권한·배포 검수 남음 |

분모를 **키 개수**가 아니라 **마케터 한 건을 끝내는 단계**로 바꿔야 한다.

## 1. 제품 축과 레퍼런스

메인 기능은 **NL → (스키마/값 조회) → 일관된 SQL**. ACC는 호스트다. 레퍼런스 1순위는 텍스트투SQL·시맨틱 레이어 제품. ACC/Journey는 배치(반영) 단계만.

| 제품 | 하는 일 | UI에서 가져올 것 |
|---|---|---|
| Snowflake Cortex Analyst | NL + **시맨틱 모델**(사람이 검증한 의미). SQL은 검사 가능 | 해석을 칩/한 줄로 보여 주고 SQL은 접기 |
| Databricks Genie | 카탈로그·예시로 조회(내부 MCP에 가까움). Inspect로 SQL 검토 | 사용한 조각(frag)을 1급. 생성 ≠ 확정 |
| ThoughtSpot Sage | 검색형 NL. 사람 큐레이션 모델 | 비개발자 카피. “맞나요?”가 기본 |
| Vanna / Defog | NL→SQL→표. 히스토리 사이드바. 권한 | 목록=이전 질문 재실행. Draft 클릭=그 질의 복원 |
| Queryfy / SQLMate | 히스토리 pin·검색. 애매하면 되묻기. 파괴적 연산은 승인 | 불확실=질문. 반영 전에 확인 |
| Amplitude / Mixpanel cohort | 조건 만들고 **Save**. Saved에서 골라 재사용 | 임시=작업본. 저장본=재사용. Create 한 번 |

공통 UI: **질문 → 해석(칩) → SQL 미리보기 → 저장/재사용**. Create를 두 번 하지 않음.

ACC 호스트만: 저장본을 custom activity에 넣고 explorer에서 WKF를 연다 (C-1·C-2).
