## 3. #161 — HUMAN_CONSOLE 재배포 체크리스트

**AI는 이 절을 PASS 처리하지 않는다.** 운영자만 체크.

### 순서 고정 (JS 라이브러리 먼저, JSSP 나중)

1. **JS 라이브러리 재등록** — `Administration > Configuration > JavaScript codes`  
   본문 전체 교체 → Save. **`libs:` allMatch에 포함되므로 아래는 전부 필수**(권장 아님).

   **A. 파이프라인 코어** (이미 159면 스킵 가능 — 배너에 안 나온 모듈)
   - `testWooRepository.js` · `testWooFragments.js` · `testWooFoundry.js`
   - `testWooCommon.js` · `testWooEnv.js` · `testWooConfig.js`
   - `testWooLlm.js` · `testWooCompiler.js` · `testWooGates.js`
   - `testWooLifecycle.js` · `testWooEmbedding.js`

   **B. 배너에 이름 나온 모듈 — 지금 재등록 필수** (`__v` 없는 구버전 또는 미등록)
   - `testWooMatch.js`
   - `testWooProbe.js`
   - `testWooDedup.js`
   - `testWooToolkit.js`
   - `testWooFeasibility.js`
   - `testWooStudioContext.js`
   - `testWooWorkflowClone.js`
   - `testWooWorkflowUi.js`

   > 2026-08-12 실측: 코어는 159 반영됐으나 B그룹 8개가 배너에 남음 → B만 추가 재등록하면 배너 소멸 예상.

2. **JSSP 파일 배포** — `Dynamic JavaScript Pages` · `new_ver/jssp/*.jssp` 전체(폐기 AuthDebug 제외)

3. **Studio 재오픈** 후 진단 패널(`#twDiagLog`) 확인:
   - `TW-BOOT v=159`
   - `libs: …` 행의 모든 `__v` 가 **159**
   - 불일치 시 상단 배너 경고(alert 없음) → 해당 모듈만 1번 재등록

4. **조건 1건 입력 → [생성]**
   - `LIB_NOT_LOADED: woo:…` 가 보이면 → 해당 JS Code 미완료
   - 정상 진행(queued / SQL / unmatched 안내)되면 **#160 종료** · 이후 **R4(#162)** 착수 가능

### 주의

- 화면의 `TW-BOOT v=159` 는 **JSSP 버전**일 뿐 JS 라이브러리 버전을 보장하지 않는다.
- 반드시 **`libs:` 행**을 확인한다.
- 배포 후 Generate가 또 `testWoo.repo is undefined`(구 메시지)면 JSSP도 미배포 — #160 가드가 안 탄 것.
