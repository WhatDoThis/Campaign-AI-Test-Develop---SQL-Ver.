 -> 없으면 새 SQL 등록만 있음.
 -> 10개 이상이면 유사도 높은 순서대로 10개만 제공.
3. SQL 생성 또는 목록 선택 시 분기.
 1) 새 캠페인 생성(새 SQL 생성) -> 프로그램 선택 -> 캠페인 생성 또는 선택 -> 워크플로우 생성 또는 선택.
  - 생성된 SQL은 반영되기 전에는 캐시에만 있는 형태로 워크플로우 뎁스에서 반영까지 가야 적용.
  - 브래드크럼: 선택 단계 또는 SQL 목록 단계로 이동. 목록에선 여전히 캐시 저장된 생성한 SQL 보임.
  - 뒤로가기: 선택 단계 또는 SQL 목록까지 뒤로가기 가능. 목록에선 여전히 캐시 저장된 생성한 SQL 보임.
  - 초기화: 빈 SQL 목록. 즉, 초기 진입단계로 이동되며 워크플로우 선택 후 반영까지 완료되지 않은 SQL 또한 목록에서 제거됨.
  - 창 종료 또는 콘솔 종료 등: 반영까지 완료되지 않은 SQL 휘발.

 2) 기존 캠페인 선택(기존 유사 SQL 중 선택) -> 해당 조건이 반영되어 있는 프로그램/캠페인/워크플로우 정보로 이동.
  - 브래드크럼/뒤로가기: 직전인 SQL 목록 단계로 이동. 목록에선 여전히 캐시 저장된 생성한 SQL 보임.
  - 초기화: 빈 SQL 목록. 즉, 초기 진입단계로 이동되며 워크플로우 선택 후 반영까지 완료되지 않은 SQL 또한 목록에서 제거됨.
  - 창 종료 또는 콘솔 종료 등: 반영까지 완료되지 않은 SQL 휘발.


즉, 기존에 순서에서 가장 마지막이었던 SQL 생성 및 선택을 첫번째로 올리고 매핑을 이후에 하는 방향.
