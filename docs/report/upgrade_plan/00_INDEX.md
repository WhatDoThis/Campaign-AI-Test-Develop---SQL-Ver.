## 3. 차수 답변 형식 (운영자용)

운영자가 받는 것: **배포 목록 + HUMAN 테스트 + 다음 키**.  
쓰는 법: **할 일은 빠짐없이, 설명은 짧게.** 초보자가 “어디 가서 뭘 누르면 되는지”만 보면 되게.

### 쓰기 원칙

| 한다 | 안 한다 |
|---|---|
| 짧은 문장 · 표 · 번호 목록 | 배경 소설, 같은 말 반복, 파일 통째 인용 |
| 용어는 **처음 한 번만** 풀어쓰기 | 매 단락 아키텍처 재설명 |
| 가이드 = 클릭/입력/기대화면 | “왜 이렇게 설계했는가” 장문 (그건 가이드 md에만) |
| 배포는 **복사해서 콘솔에 쓸 표** | “관련 JS를 재배포하세요” 한 줄로 끝 |

풀어쓰기 예: `v=` = Studio 주소 끝의 버전 숫자. 없으면 옛 화면. `__v` = JS 라이브러리 안 버전.

### 시작 (코드 치기 전 · 4줄)

```
차수: <키>
가이드: <경로 §>
선행: PASS | BLOCKED (막히면 여기서 중단)
모드: 구현 | HUMAN만 | 문서만
금지: 이번 차수 밖 파일 · Match Option ON · COUNT
```

한 Chat = 키 1개. UX-ST1과 R6은 파일 다름 → 묶지 말 것.

### 끝 (코드/문서 후 · 아래 4덩이 빠지면 미완)

**1. 결과** — 3줄 이내. 무엇이 됐고, 무엇이 안 됐고, 화면에서 뭐가 바뀌나.

**2. 배포 목록** — 코드가 바뀐 차수만. 순서 고정: **스키마 → JS 라이브러리 → 폼/navtree → JSSP**.

```
배포 (이 순서)
1. [콘솔 종류] 내부이름    로컬파일                    확인할 것
2. ...
Studio URL에 v=<n> 보이는지 (litmus). 없으면 강력 새로고침.
```

종류 예: JS Code = `woo:testWooLlm.js` · JSSP = `/woo/testWooAiStudio.jssp`.  
안 바뀐 파일은 적지 말 것. 배포 없으면 **「배포 없음」** 한 줄.

**3. HUMAN 테스트** — AI가 PASS로 처리하지 않음. 단계마다: 어디 → 뭘 함 → 뭐가 보여야 함 → 회신 문구.

```
테스트
1. Studio 연다. 주소에 v=<n> 확인.
2. 입력: <문장 그대로>
3. 기대: <SQL/칩/버튼. 한 줄>
4. 회신: PASS 또는 FAIL + 화면에 보인 것
```

**4. 다음** — 키 1개 + 아래 블록.

```
차수: <다음 키>
가이드: <경로>
선행: ...
모드: ...
금지: ...
```
