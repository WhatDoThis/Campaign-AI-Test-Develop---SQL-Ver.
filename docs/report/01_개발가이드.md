### 논리명 vs 물리명 — `sql_text` 작성 필수 규칙

`sql_text` / `key_column` 은 원시 SQL 이므로 **물리명만 통한다.** ACC 는 스키마
속성에 `sqlname` 이 없으면 타입 접두사를 붙여 물리 컬럼명을 자동 생성한다.
논리 속성명을 그대로 쓰면 `column does not exist` 로 실패한다.

`woo:testWooSampleCustomer` 실측값 (2026-08-06 배포 스키마 기준):

| 논리 속성명 | 물리 컬럼명 | 타입 |
|---|---|---|
| `id` (PK) | `iTestWooSampleCustomerId` | long |
| `customer_id` | `sCustomer_id` | string |
| `age` | `iAge` | long |
| `region` / `gender` / `status` / `email` / `name` | `sRegion` / `sGender` / `sStatus` / `sEmail` / `sName` | string |
| `marketing_consent` / `sms_consent` | `iMarketing_consent` / `iSms_consent` | byte |
| `birth_date` / `created_date` | `tsBirth_date` / `tsCreated_date` | date/datetime |

접두사 규칙: `s`=string, `i`=정수/byte/boolean, `ts`=날짜·시각, `d`=double,
`m`=memo. PK 는 `i{PascalCase스키마명}Id`.

| 구분 | 논리명 사용 | 물리명 사용 |
|---|---|---|
| `xtk.queryDef` / `xtk.session.Write` / input form `xpath` | ✅ | ✗ |
| `sql_text` · `key_column` · `sqlSelect` · `sqlGetInt` · `populationCountSql` | ✗ | ✅ |

**테이블명은 `sqltable` 선언값 그대로다.** 네임스페이스 접두사를 붙이지 않는다.
`WooTestWooSampleCustomer` 같은 이름은 존재하지 않는다.

**물리명 확인 방법.** 추정하지 말고 툴킷 `describe_schema` 의 `sqlColumn` 값을
쓴다. 이 값은 배포된 확장 스키마의 `@sqlname` 이라 항상 실제 컬럼과 일치한다.
`probe_values` 는 논리명·물리명 어느 쪽을 넘겨도 내부에서 물리명으로 해석하지만,
`probe_sql` 과 최종 `sql_text` 는 호출자가 물리명을 써야 한다.

**행 수 주의.** ACC 는 테이블마다 PK=0 기술 레코드 1건을 유지한다. 그래서
`SELECT COUNT(*)` 는 `queryDef operation="count"` 보다 항상 1 크다
(샘플 고객 101 vs 100). `populationCountSql` 의 분자(`probe.total`)도 원시 SQL 이라
같은 기준이므로 `COUNT(*)` 를 그대로 쓴다.

## 섹션 6 — Foundry 배포 선행조건 (WKF_testWooFoundry)

Foundry(미매칭 슬롯 → fragment 자동 생성)는 **읽기 SQL 실행 권한**과 **단일 실행 보장**이 전제다.
둘 중 하나라도 빠지면 조용히 오작동하거나 중복 fragment가 생성된다.

### 1) 오퍼레이터 `sql` named right — **필수**

경로: `Administration > Access management > Operators` (또는 Operator groups)

- **`WKF_testWooFoundry` 를 실행하는 오퍼레이터에 `sql` named right 필수.**
- 근거: 공식 문서 `sqlGetInt` — *"The operator must have the 'sql' right to use this function,
  otherwise an exception is raised."*
  ([sqlGetInt](https://experienceleague.adobe.com/developer/campaign-api/api/f-sqlGetInt.html))
- 권한이 없으면 `testWoo.probe.preflight()` 가 `NO_SQL_RIGHT` 로 실패하고,
  배치는 **큐 상태를 바꾸지 않고 중단**된다(재시도 가능). 오류 ID 접두사 `FFPERM`.
- 확인: WF JavaScript code 액티비티에서

```javascript
loadLibrary("woo:testWooProbe.js");
logInfo(JSON.stringify(testWoo.probe.preflight()));
```

  → `{"ok":true}` 가 아니면 권한 부여 후 재확인.

### 2) 워크플로우 동시 실행 금지 (단일 인스턴스)

경로: WF 열기 → `Edit > Properties`(또는 속성 아이콘) → **Execution** 탭

- **"Do not launch if the workflow is already running"**(동시 실행 금지) 계열 옵션을 켠다.
  버전에 따라 라벨이 다르므로 *이미 실행 중이면 새 인스턴스를 만들지 않는* 설정을 선택.
- 스케줄러는 5분 주기. 이전 배치가 길어져도 새 인스턴스가 겹치지 않게 한다.
- 코드 측 2중 가드: `processBatch()` 가 `processing` 레코드 존재 시 `skipped:true` 로 빠지고,
  30분 이상 정체된 `processing` 은 `queued` 로 되돌린다(`testWooEnv.js` → `foundry.staleProcessingMinutes`).
- **완전한 원자성은 이 WF 설정에 의존한다.** `_claimQueue` 의 재조회 검증만으로는
  두 인스턴스 동시 진입을 막지 못한다.

### 3) 배포 순서 (반드시 이 순서)

**스키마 재등록 → DB 구조 업데이트 → JS library 배포 → JSSP 배포 → navtree**

| 순서 | 대상 | 비고 |
|---|---|---|
| 1 | Data schemas 재등록 | `testWooAiFragment` / `testWooAiSql` / `testWooAiRequestQueue` / `testWooAiGapLog` |
| 2 | **Update database structure** | 신규 컬럼이 물리 테이블에 반영돼야 함 |
| 3 | JavaScript codes | 로드 순서 `Env → Config → … → Foundry` |
| 4 | JSSP (`/woo/`) | Studio·Generate·Validate·Register·QueueStatus·FragmentReview |
| 5 | navtree | 확장 컬럼(`@version`/`@active`/`@dedup_verdict`)은 1~2 완료 후에만 |

> 2번을 건너뛰고 JS만 배포하면 queryDef 가 XTK 스키마 오류로 실패한다.
> `_getQueue` 는 이 오류를 **"스키마 배포가 선행되지 않았습니다"** 메시지로 치환해 던진다.

### 5) ACC 읽기 SQL 규약 (코드 계약)

| 함수 | 규약 |
|---|---|
| `sqlSelect(format, query)` | 1번째 인자는 **라벨이 아니라 결과 XML 스키마** `"docName,[fieldXPath:type[:length],]*"`. 반환은 **XML 객체**(배열 아님) → `.length` / `[0]` 접근 금지, `for each` 순회 ([문서](https://experienceleague.adobe.com/developer/campaign-api/api/f-sqlSelect.html)) |
| SELECT 별칭 | 모든 프로브 쿼리는 `AS tw_key` / `AS tw_val` 처럼 **명시적 별칭**을 주고 format 과 1:1 대응 |
| `sqlExec` | **전면 금지.** 조회는 `sqlSelect`/`sqlGetInt`, 레코드 CRUD 는 `xtk:session#Write` |
| `application.getSchema` | 스크립트 종료까지 메모리 유지 → `search_columns` 는 namespace당 **30개** 상한, 초과 시 `partialScan:true` ([문서](https://experienceleague.adobe.com/developer/campaign-api/api/m-Application-getSchema.html)) |
| XML 속성 파싱 | 정규식 금지, **E4X** 사용 (ACC 스키마는 속성 순서 자유 · `label` 생략 가능) |
| `application.getSchema` 반환형 | **Schema 클래스**이며 공식 메서드는 `toDocument()` 하나뿐. `toXMLString` 은 DOMElement 메서드이므로 `sch.toDocument().documentElement.toXMLString()` 을 경유한다. Schema 에 직접 호출하면 런타임 예외 ([Schema](https://experienceleague.adobe.com/developer/campaign-api/api/c-Schema.html) · [toDocument](https://experienceleague.adobe.com/developer/campaign-api/api/m-Schema-toDocument.html)) |
| `queryDef` `getIfExists` | **엘리먼트 자체**를 반환한다(무매치는 빈 엘리먼트). `select` 만 `<xxx-collection>` 으로 감싼다 → `res.<root>[0]` / `.length` / `for each` 금지. 존재 판정은 `String(res.@id \|\| "") === ""`, `<select>` 에 `<node expr="@id"/>` 필수 ([문서](https://experienceleague.adobe.com/developer/campaign-api/api/sm-queryDef-ExecuteQuery.html)) |
| 물리 컬럼명 | **추정 금지 · 조회는 필수.** `sqlname` 미지정 시 물리명은 타입 접두사 + 이름으로 자동 생성된다(`customer_id` → `sCustomer_id`). 유일한 정답은 **배포된 확장 스키마의 `@sqlname`** 이며, 툴킷 `describe_schema` / `search_columns` 가 `sqlColumn` 으로 노출한다. `sqlColumn` 이 빈 값이면 SQL 컬럼이 아니다(XML 저장 필드) → 조회 불가. 상세 대응표는 섹션 2 "논리명 vs 물리명" 참조 ([문서](https://experienceleague.adobe.com/en/docs/campaign-classic/using/configuring-campaign-classic/schema-reference/database-mapping)) |
| 물리 테이블명 | **`sqltable` 선언값 그대로.** 네임스페이스 접두사를 붙이지 않는다(`WooTestWooSampleCustomer` 는 없음). PostgreSQL 은 미인용 식별자를 소문자로 접기 때문에 오타 시 소문자 이름으로 오류가 난다 |
| 기술 레코드 | ACC 는 테이블마다 **PK=0 레코드 1건**을 유지한다 → `SELECT COUNT(*)` 는 `queryDef operation="count"` 보다 항상 1 크다. 원시 SQL 끼리 비교하는 경우(`populationCountSql` ↔ `probe.total`)에는 기준이 같으므로 보정하지 않는다 |
| 샘플 재현성 | Oracle `FETCH FIRST` / MSSQL `TOP` 은 `ORDER BY` 없으면 비결정적 → `limitSelect` 가 기본 `ORDER BY 1` 을 붙인다. `auditSample` 은 승인 근거 자료이므로 재현성 필수 |
| 행 제한 SQL 조립 | **`dialect().limitSelect(selectList, fromClause, whereSql, n, opts)` 가 유일한 래핑 지점.** `opts = {distinct, orderBy}`. `limit(sql, n)` 은 **제거됨**(파생 테이블 이중 래핑 유발) |
| `DISTINCT` 위치 | **`selectList` 문자열에 `DISTINCT` 직접 삽입 금지.** `opts.distinct = true` 로 넘긴다. T-SQL 은 `SELECT [ALL\|DISTINCT] [TOP n] select_list` 순서라 `SELECT TOP n DISTINCT …` 는 구문 오류 ([문서](https://learn.microsoft.com/en-us/sql/t-sql/queries/select-transact-sql)) |
| 파생 테이블 `ORDER BY` | MSSQL 은 뷰·인라인 함수·**파생 테이블·서브쿼리·CTE 내부의 `ORDER BY` 를 거부**한다(TOP/OFFSET 동반 시에만 허용). 완성된 SELECT 를 감쌀 때는 `{orderBy: null}` 로 호출하고, 집합연산(`EXCEPT`/`MINUS`) 내부에도 `ORDER BY` 를 만들지 않는다 ([문서](https://learn.microsoft.com/en-us/answers/questions/1061604/the-order-by-clause-is-invalid-in-views-inline-fun)) |
| 예외 처리 | 빈 `catch {}` 로 삼키지 않는다(최소 `logWarning`). 스키마 로드 실패가 "0건"으로 위장되면 Triage 가 근거 없이 `no_column` 을 낸다 |
| 방언 지원 범위 | **ACC v7 은 PostgreSQL·Oracle·MSSQL 을 지원하지만 본 시스템은 PostgreSQL 에서만 실동 검증된다.** Oracle/MSSQL 분기는 `tools/checkDialectSql.js` 의 **문자열 정합까지만** 보증하며 실행 검증은 하지 않는다. `preflight()` 가 PG 아닌 DBMS 에서 `logWarning` + `dialectVerified:false` 를 돌려주되 **차단하지는 않는다** ([호환성 매트릭스](https://experienceleague.adobe.com/en/docs/campaign-classic/using/release-notes/compatibility-matrix)) |
| `getDBMSType` 데이터소스 | 인자 생략 시 `nms:default` 기준이다. FDA 로 외부 데이터소스를 붙이면 fragment SQL 대상 방언이 달라지므로 `dialect(dsName)` 확장이 필요하다 — **현재 미구현, `dialect()` 상단 주석으로만 표기** ([문서](https://experienceleague.adobe.com/developer/campaign-api/api/m-Application-getDBMSType.html)) |

### 6) 배포 마지막 단계 — 스모크 실행 (필수)

`tools/checkRhinoSyntax.js` 는 구문 오류만 잡고 **API 시그니처 오용은 잡지 못한다**
(문법 정상 + 존재하지 않는 메서드 호출 → 런타임 전멸). 따라서 배포 절차의 마지막 단계로
`new_ver/tools/testWooSmoke.js` 를 WF JS 액티비티에 붙여 **1회 실행한다.**

| 단계 | 검증 대상 |
|---|---|
| 1 | `testWoo.*` 14개 모듈 전역 정의 (loadLibrary 실패 즉시 검출) |
| 2 | `probe.preflight()` → `ok:true` (`sql` named right) + `dbms`/`dialectVerified` 요약 기록 |
| 3 | `sqlSelect("row,@x:string", …)` 반환 XML 구조 `logInfo` (파싱 가정 확정) |
| 4 | `describe_schema` 속성 배열 비어있지 않음 (Schema `toDocument` 경로 회귀 검출) |
| 4b | `describe_schema` 가 `sqlColumn`(=`@sqlname`) 노출 + `name` 과 다른 컬럼 1개 이상 존재 (논리명 유출 회귀) — 실행 없음 |
| 4c | `probe_values` 에 **논리명**(`region`) 을 넣어 물리명(`sRegion`) 해석 + 실제 SQL 실행 확인 |
| 5 | `search_columns` 1건 이상 + `schemaLoadFailed` 아님 |
| 5b | 방언별 `limitSelect` 생성 SQL 문자열 일치 (mssql/oracle/pg + 파생 테이블 래핑) — 실행 없음 |
| 6b | 존재하지 않는 id(`-1`) 조회 → **예외 아닌 `null`** (`getIfExists` 규약) |
| 6a | 큐 더미 1건 insert → `foundry.peekQueue`(=`_getQueue`) + `repo.getQueueStatus` 양쪽 조회 → 삭제 |

> 실패 1건 이상이면 마지막에 `logError` 가 찍힌다. **배포를 완료로 간주하지 말 것.**
> `SKIP` 은 전제 조건 미충족(4c 는 `woo:testWooSampleCustomer` 미배포 시 SKIP)이며
> PASS 로 세지 않는다. 요약에 `n skipped` 로 표기되므로 사유를 확인할 것.
> 4b 를 표준 스키마(`nms:recipient`)로 하는 이유: Adobe 가 `sqlname` 을 명시해
> (`email`→`sEmail`) 논리명·물리명이 다른 컬럼 존재가 보장되고 SQL 실행이 없어 비용이 0 이다.
> 4c 를 샘플 테이블(100행)로 한정하는 이유: `probe_values` 는 `COUNT(DISTINCT …)` 를
> 실행하므로 대형 표준 테이블에서는 스모크 비용이 과도해진다.
> 6a 더미 레코드는 `finally` 에서 삭제되며, 삭제 실패 시 `logError` 로 수동 정리를 안내한다.
> 6a 가 두 경로를 모두 확인하는 이유: `_getQueue` 는 Foundry 큐 처리 경로,
> `getQueueStatus` 는 Studio 조회 경로로 **둘 다 `operation="getIfExists"`** 이기 때문이다.
> `peekQueue` 는 이 점검을 위한 읽기 전용 진입점이며 운영 로직에서는 호출하지 않는다.
