# AI SQL 타깃 검증 워크플로 (ACC v8 / PostgreSQL)

> **HUMAN PASS · 2026-08-14**  
> 검증 WKF 실행 완료. Studio가 만든 SQL로 **실제 타겟이 추출됨**.  
> 이 PASS는 ST0(SQL이 DB에서 돌아감)이다. R6(커스텀 액티비티 주입·WKF 열기)가 아니다.

## 1. 목적
- AI Studio가 생성한 SQL을 **실제 DB에서 실행**해 타깃이 뽑히는지 검증한다.
- 결과를 **임시 테이블**에 적재하고, **트랜지션 우클릭 → 대상 표시**로 눈으로 확인한다.
- 케이스별 실행 이력을 로그 테이블에 누적해 반복 실행(G4 재현성 검증)에 재사용한다.

## 2. 컴포넌트 배치도

```
시작
 └─▶ ① JS code   "1_준비"     : 변수 세팅 · 임시테이블 DROP · 로그테이블 CREATE
      └─▶ ② SQL code "2_실행"  : AI SQL을 감싸 CREATE TABLE AS (유일한 코드 삽입 지점)
           └─▶ ③ JS code "3_목록화" : 건수 카운트 · 런로그 INSERT · ID 목록 문자열 생성
                └─▶ ④ Query   "4_타깃"  : 변수 IN 조건으로 모집단 생성  ← ★ 여기 트랜지션에서 확인
                     └─▶ ⑤ 대기(Wait)  : 임시테이블 자동 정리 방지 / 확인 후 수동 정지
```

## 3. 단계별 역할

| 단계 | 활동 | 하는 일 | 출력 |
|---|---|---|---|
| ① | JS code | 임시테이블·로그테이블 준비, 케이스 ID 지정 | `vars.aiTmpTable`, `vars.aiCaseId`, `vars.aiSchema` |
| ② | SQL code | AI SQL을 서브쿼리로 감싸 고객 테이블과 JOIN → 임시테이블 생성 | `tmp_woo_ai_target` (고객 전체 컬럼) |
| ③ | JS code | 건수 집계, 런로그 적재, ID 목록 문자열 조립 | `vars.aiIdList`, `vars.recCount` |
| ④ | Query | 대상 차원 = 고객 스키마, `Customer ID ~ 다음 값 중 하나` 조건 | 아웃바운드 트랜지션 모집단 |
| ⑤ | 대기 | 워크플로 종료 시 임시테이블 삭제되는 것 방지 | — |

## 4. 핵심 변수

| 변수 | 값 예시 | 비고 |
|---|---|---|
| `vars.aiTmpTable` | `tmp_woo_ai_target` | 이름 고정 → Query 조건 재수정 불필요 |
| `vars.aiCaseId` | `C1`, `C2` … | 케이스마다 이 값만 변경 |
| `vars.aiSchema` | `woo:testWooSampleCustomer` | 실제 스키마 `namespace:name` |
| `vars.aiIdList` | `CUS0031','CUS0056','CUS0082` | **바깥 따옴표 없음**(빌더가 붙임) |
| 로그 테이블 | `tmp_woo_ai_runlog` | caseId / rowCount / tsRun / workflowId |

## 5. Query 조건 설정 (④)

| 항목 | 값 |
|---|---|
| 대상 차원 | Test Woo Sample Customer |
| 표현식 | Customer ID |
| 연산자 | `~ 다음 값 중 하나` (is included in) |
| 값 | `$noescaping(vars/@aiIdList)` |

- 고급 모드 불필요. `$(...)`가 아니라 **`$noescaping(...)`** 을 써야 따옴표가 이스케이프되지 않는다.

## 6. 시행착오 → 확정 규칙

| 증상 | 원인 | 확정 규칙 |
|---|---|---|
| `PGS-220000 column specified more than once` | `c.sCustomer_id` + `t.*` 중복 | ②는 `SELECT c.*` 단일 소스만 |
| 뷰어가 임시테이블을 못 잡음 | JS 활동은 모집단을 트랜지션에 넘길 수 없음 | 모집단 생성은 **Query 활동만** 가능 |
| 대상 표시 비어 있음 | 스키마명·PK 불일치 | 스키마 `autopk="true"` → 실PK는 `iTestWooSampleCustomerId`, `customer_id`는 보조키 |
| `XTK-170016 SQL 표현식 권한 없음` | queryDef `sql=` 절 사용 | queryDef 서브쿼리 대신 **ID 목록 문자열** 전달 |
| `IN (''1030,1055'')` | `$()` 가 값을 문자열 리터럴로 감쌈 | `$noescaping` 사용 |
| `IN (''CUS0031','CUS0056'')` | 코드와 빌더가 따옴표를 이중으로 붙임 | 목록은 **구분자 따옴표만** 포함, 바깥 따옴표는 빌더에 위임 |

## 7. 제약 사항
- 8.9.1+ 보안 정책상 SQL code에서 `TRUNCATE` / `CREATE INDEX` 금지 → `DROP TABLE` + `CREATE TABLE AS`만 사용.
- ① 단계에서 `TRY/CATCH` 금지 (PostgreSQL 트랜잭션 오염).
- 테이블명에 `wkf` 접두사 사용 금지 (자동 정리 대상).
- JST 템플릿이 `%`를 오파싱하므로 `LIKE '%…%'` 회피.
- ID 목록 리터럴 방식은 **수백 건 규모까지**. 수만 건이면 Query 조건을 서브쿼리로 전환하거나 오퍼레이터에 SQL 표현식 권한 부여 필요.

## 8. 반복 실행 절차
1. ① 의 `aiCaseId` 변경 → ② 에 새 AI SQL 붙여넣기 → 실행.
2. ④ 아웃바운드 트랜지션 우클릭 → 대상 표시로 건수·레코드 확인.
3. 누적 결과는 `tmp_woo_ai_runlog`를 `tsRun DESC`로 조회.
4. 동일 문장 10회 반복 시 `iRowCount`가 전부 같아야 함(G4 재현성 판정 기준).

- **커버**: SQL 문법 유효성, 실제 실행 가능 여부, 타깃 건수, 결과 재현성.
- **미커버**: 값이 사용자 발화에서 유래했는지(`unsourced_value` 문제), 상위어 그룹 확장 정책(core/edge/basis), 프래그먼트 중복 등록 — 이건 #174/#175 트랙에서 별도 처리.
